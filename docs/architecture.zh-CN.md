# 实现原理

[English](architecture.md)

## 两项设置，一篇笔记

原生设置只声明 `digest.interests`（文本）和 `digest.frequency`（日报／周报）。空领域不启动任务。来源与研究深度不再暴露给用户，内部使用四个来源与标准研究。

`src/settings.ts` 用五秒期限读取两项设置，解析中英文分隔符并去重，限制五个领域、每个 60 字。无效或读取失败时停止自动生成，不使用猜测的领域或频率。缺少设置能力时说明需要兼容宿主。

`src/digest.ts` 在插件激活时注册统一命令 `generate-digest`，而非等用户打开面板。设置在激活、面板打开、手动刷新、执行前及每 30 秒重新读取。宿主当前没有设置变更通知，不依赖未实现的事件 API。读取与计划同步串行执行，未变化的计划不重复写入；停用插件清理定时器、命令与请求。

## 计划与保存

使用既有 `schedules.upsert/remove`，固定 key 为 `hotspot-digest`。日报表达式为 `0 9 * * *`，周报为 `0 9 * * 1`，设备时区，错过跳过。更改频率更新同一条计划。暂停状态保存在插件存储，清空领域或无效设置移除计划。同步失败明确提示并重试，不显示为已成功开启。仅桌面端保持运行时执行，不部署后台研究服务。

每日窗口为过去 24 小时，每周为过去 7×24 小时，截至本次生成开始时间，不是自然日／自然周完整归档。期次去重按本地日历：日报为日期，周报为周一所在周。手动和定时生成共用互斥流程，同期已保存则复用。手动生成可以提前占用本期名额，不会再在计划时间重复生成；修改领域不会重做已保存的同一期。

一轮包含全部关注领域，只有一个 Run 和一篇笔记。完成后用 `notebooks.list` 查找 `nb_inbox`，否则选第一个笔记本，通过 `notes.create` 保存。无资料也保存明确说明覆盖不足的笔记。保存失败保留已完成草稿，下次只重试保存。笔记 ID 同时记录到 Run 和最多四条独立期次索引，避免 30 条历史淘汰导致同一期再次生成。此去重限当前设备。

关闭面板不停止生成，主动取消／停用插件中止请求。暂停或清空设置会取消进行中的自动生成，但不取消手动生成。已发出的 `notes.create` 无通用取消契约，可能仍完成；收到 ID 后必须持久化。**宿主未提供幂等创建或原子“创建笔记并保存插件状态”能力**：若笔记成功创建但响应丢失，或创建后进程崩溃，重试可能重复。幂等写入与设置变更订阅仅为未来通用能力建议，本插件未假装它们已实现。

## 搜索与报告

`src/engine.ts` 保留通用研究引擎。新汇总对每个领域独立规划，保留原领域查询，可补充一个准确英文查询。每个来源／查询最多十条，最多两个并发请求；HN 评论补充最多两次请求。所有请求经过 `src/runtime.ts` 注入的通用宿主传输，`src/sources.ts` 的平台请求语法、XML／JSON 解析都随插件打包。

每个领域先做日期和词汇相关性过滤，使用查询扩展识别英文资料。按领域轮流选取，最多 40 条，避免一个领域挤占全部位置；相同规范化 URL 合并并保留全部匹配领域。新日报／周报剔除日期未知、无效、过旧或未来资料；旧版研究保留原有日期未知标签。来源原始排序与关键词重合参与排序，不比较跨平台点赞数，也不宣称全网趋势。

AI 对全部资料进行相关性筛选，再生成一篇按所有关注领域分组的报告。每个领域最多五条变化，说明发生了什么、为何值得关注；推断须标注，资料不足不能凑数。来源文字是不可信数据，不执行其中指令；标题摘要不得冒充全文。每个资料有全局唯一证据 ID，引用仅能指向真实取得的 URL。这验证来源，不验证结论真伪或语义蕴含。

AI 未配置／失败时生成按领域分组、明确标注“不是 AI 综合报告”的资料清单；没有资料时说明覆盖不足。报告重生成只使用原证据、窗口和领域，不重复检索，失败或取消保留原报告。已保存笔记不覆盖，更新结果可导出 Markdown。

等待上限：AI 状态十秒、规划三十秒、相关性筛选四十五秒、来源三十秒、报告九十秒。传给模型的资料最多 40 个 ID，约 56,000 字符，超长评论摘要截短。宿主模型计费取消时机仍由供应商决定。

## 界面、迁移与验证

`src/ui.ts` 只显示订阅摘要、立即生成、暂停／恢复、刷新设置与最近结果，并按 EdgeEver 的原生页面层级组织标题、设置摘要、操作和列表。普通配置仍由宿主根据 Manifest 统一渲染，面板不复制设置表单。去掉研究输入框、深度、来源选择和逐话题任务管理。来源覆盖与证据放进折叠详情；报告经 DOMPurify 和 marked 安全渲染，资料摘要为纯文本。Shadow DOM 隔离样式。

`src/store.ts` 串行保存当前设备的状态快照。继续使用版本 1，新增字段均可选：`Run.digest`、`Evidence.interests`、`digestPaused`、`digestNotes`；不做破坏性数据迁移。启动时先逐个移除旧 watch 计划，成功后才把 scheduled 置为 false。失败保留标记并阻止启用新计划，后续重试。旧研究、追踪记录、比较链接和追问仍保留；不自动把它们变成新订阅。中断的旧运行仍标记为 interrupted。

确定性测试覆盖设置、周期切换、去重、暂停、保存重试、迁移、失败来源、日期、领域公平性和 UI 安全。浏览器通过显式模拟宿主验证交互与布局；不使用真实模型、不写真实笔记，不视为桌面调度时钟或生产宿主验证。

## 宿主边界

只依赖通用网络、AI、设置、存储、笔记和调度能力。`ResearchBridge`、来源类型、领域结构、提示词和报告编排都是插件内部实现，绝不增加宿主研究路由、来源 SDK 类型或部署第二个服务。新增通用网络／AI 能力仍须正式发布后才能稳定安装，参见[能力契约](host-capabilities.zh-CN.md)。v0.5.0-preview.1 仍为预览版，不修改 EdgeEver checkout。
