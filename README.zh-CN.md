# EdgeEver 热点追踪

[English](README.md) · [实现原理](docs/architecture.zh-CN.md)

输入关心的话题，了解近期变化，把带来源的研究报告保存为 EdgeEver 笔记。用户无需安装 Last30Days、Python、Docker，也无需额外部署研究服务。

**当前状态：0.4 开发候选，尚未发布。** 来源请求、解析、排序和报告编排均在插件包内执行。EdgeEver 本地开发代码已提供通用 AI 生成与公开 HTTPS 传输，不包含研究专用路由，也不需要源码注入脚本。浏览器联调已取得真实证据、生成带引用的报告，并验证失败后用保留资料重新生成。这两项通用 API 仍需随 EdgeEver 正式版本发布，才能支持普通用户直接安装。

参见[通用宿主 API 契约](docs/host-capabilities.zh-CN.md)。此前 v0.1–v0.3 预览版采用的专用宿主适配方案已废弃，不应再应用其补丁。

## 0.4 架构调整

- 四个平台的来源适配器和解析依赖随插件打包，通过通用 `context.network.fetch` 和四个声明域名请求。
- 移除 `research:search` 权限、宿主来源契约、研究路由、客户端适配与源码注入脚本。
- 提示词、查询规划、相关性筛选、报告生成流程全部属于插件；宿主只承担通用模型调用。
- 来源不可读时说明覆盖不足，不使用隐藏宿主路由、浏览器 Cookie 或第三方代理兜底。

## 0.3 新增：原生插件设置

从「插件市场 → 热点追踪 → 插件设置」或插件工具菜单进入，设置默认时间范围（7／30／90 天）、研究深度和四个来源开关。初始默认值为最近 30 天、标准研究、全部四个来源。

设置保存在当前设备，关闭并重新打开研究面板后生效；面板里的临时调整保留到本次关闭为止。已有研究和追踪任务保留原来的配置。如果所有默认来源都关闭，需要先选择至少一个来源才能开始。设置不会开启定时任务，也不需要再填 API Key。

未提供设置接口的宿主保留原有控件与默认行为；设置读取失败或值无效时会说明并回退。完整功能仍需上文说明的通用能力。

## 0.2 新增与优化

- 每次研究可选择来源，追踪任务记住原始来源与研究深度；已有追踪沿用全部来源和标准深度。
- 可用已有证据生成或重新生成 AI 报告，无需再检索；失败或取消重试会保留原报告。
- 研究历史按话题搜索，证据按来源筛选；展示仅标题摘要与日期未知的数量，区分资料已保留与 AI 报告已完成。
- 请求设置等待上限，避免一直处理中；临时无法读取 AI 配置时仍继续收集公开资料。
- 旧研究退出最近 30 条历史后，追踪仍保留对比链接；不同来源／深度组合可分别追踪。


## 已实现

- 研究最近 7、30、90 天的动态，提供快速浏览、标准研究、深入研究三种模式。
- 聚合新闻资讯、Hacker News、GitHub 公开 Issue/PR、Reddit 公开订阅源。
- 拆解关键词、去重、筛选相关资料，沿用 EdgeEver 默认 AI 模型生成带引用的报告。
- 基于已有证据追问，一键保存笔记，导出 Markdown 或 HTML。
- 当前设备保留最近 30 次研究和最多 30 个追踪话题，比较本轮与上轮取得的不同链接。
- 可选每日 09:00 按设备时区更新，并自动归档到指定笔记本。每日计划默认关闭，仅在桌面端保持运行时执行；错过的任务跳过。

新闻和 Reddit 提供标题／正文片段，不代表已读取文章全文或完整评论。Hacker News 每次查询为前两条结果各补充最多三条评论。GitHub 提供 Issue/PR 正文及评论数，当前不抓取评论正文。来源失败或受限会明确展示。

首版尚不包含 X、YouTube、TikTok、Instagram、无需输入主题的热点发现、全天候后台抓取，也不将检索结果数量当作全网趋势。引用只能确认来源链接确实取得，不能自动证明生成内容正确，重要结论仍应核对原文。

## 安装状态

当前架构调整分支用于评审，尚不适合安装到现有生产宿主。EdgeEver 正式版本发布已实现的通用能力后，用户通过常规插件市场安装，沿用已有 AI 设置；无需修改 EdgeEver 源码或部署其他服务。

未配置 AI 时仍可检索公开资料，界面会明确说明当前不是 AI 综合报告。模型调用按用户选择的供应商计费；来源无需新增 API 密钥，但可用性受实例网络和来源限流影响。

插件运行在 EdgeEver 的可信客户端插件环境中，并非强隔离 JavaScript 沙箱。本插件通过有权限检查的宿主接口调用能力，不读取浏览器 Cookie，也不接收 AI 供应商密钥。检索关键词经宿主通用网络传输能力发送至公开来源，解析与平台业务逻辑在插件执行；问题和资料摘要发送给已配置的 AI 供应商。研究历史、追踪列表保存在当前设备；主动保存的笔记按工作区原有机制同步。

## 开发

需要 Bun 1.3.14 或更新版本。以下是开发者命令，普通用户无需运行。

```sh
bun install --frozen-lockfile
bun run check
bun run test:live  # 仅验证 Bun 网络请求，不验证浏览器跨域或宿主 API
bun run dev        # 127.0.0.1:4178 上的插件静态开发包服务
```

仅在实现通用契约的开发宿主中安装 `http://127.0.0.1:4178/manifest.json`；缺少 `ai:generate` 或 `network:public` 的旧版 SDK 会拒绝此清单。该开发服务仅提供插件文件，不承担研究业务。修改代码后重新构建、重新安装开发清单以更新缓存包，再刷新 EdgeEver 页面。

构建输出 `dist/main.js` 单文件浏览器模块、`manifest.json`、`LICENSE` 和 `THIRD_PARTY_NOTICES.txt`。通过 GitHub Release 分发；仓库根目录的清单必须与对应 Release 的清单完全一致。标签构建默认发布为预览版；CI 只运行确定性测试和构建，不调用公开来源或 AI。

## 宿主边界

只使用通用网络、AI、设置、笔记、存储与调度 API。`src/runtime.ts` 将这些能力连接到插件自己的适配器；`src/sources.ts` 随插件打包，不复制到 EdgeEver。接口限制与验证状态见[通用能力契约](docs/host-capabilities.zh-CN.md)。本仓库不再提供向宿主源码目录写入内容的脚本。
