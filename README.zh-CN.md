# EdgeEver 热点追踪

[English](README.md) · [实现原理](docs/architecture.zh-CN.md)

设置你关心的领域，选择日报或周报，定期收到一篇带来源的热点笔记。无需部署其他研究服务，也无需填写新的 API Key。

## 怎么用

在「插件市场 → 热点追踪 → 插件设置」配置两项：

- **关注领域**：例如 `AI、独立开发、科技产品`。用逗号、顿号或换行分隔，最多 5 个领域，每个最多 60 字；留空停止自动生成。
- **生成频率**：日报为每日 09:00，覆盖过去一天；周报为每周一 09:00，覆盖过去七天。均按设备时区执行。

首次默认为周报，关注领域为空，不会自动开始。填写并保存后约 30 秒内应用，不用先研究或添加追踪任务，也无需打开插件面板。来源、时间范围和研究深度由插件处理。

每期只创建一篇汇总笔记，按关注领域分组，说明发生了什么、为什么值得关注，并附来源。默认保存到收件箱（`nb_inbox`）；没有收件箱时使用第一个笔记本。没有任何笔记本或保存失败时，结果保留在插件中，可重试保存。

打开插件可查看最近结果、立即生成，或暂停／恢复自动生成。立即生成也会自动保存，暂停只影响自动生成。当前设备同一期已有笔记时直接复用，不重复检索或创建；日报按本地日期、周报按周一开始的一周识别期次。修改领域后在下一期使用新配置；频率切换会使用对应的日报／周报期次。

**自动生成依赖 EdgeEver 桌面端保持运行。关闭应用不会继续执行，错过不补跑。** 设置和运行记录保存在当前设备，不提供跨设备全局去重。生成中关闭面板不会取消任务；可主动取消，停用插件也会中止请求。

## 笔记与资料边界

- 聚合新闻、Hacker News、GitHub 公开 Issue/PR 和 Reddit 公开订阅源，逐领域搜索、筛选并去重。
- 日报／周报只纳入日期明确、在本期时间窗口内的资料。查询结果受来源覆盖限制，不是全网热度排名。
- AI 沿用 EdgeEver 默认模型，按用户的供应商计费。缺少 AI 配置或生成失败时，保存明确标注的资料汇总，不冒充 AI 综合报告。
- 某个领域无资料或来源访问失败时明确说明，不凑数，也不推断该领域没有动态。本期完全没有资料时，保存说明资料不足的笔记。
- 新闻和 Reddit 主要提供标题摘要，不代表阅读全文或完整评论。HN 每次查询为前两条结果各补充最多三条评论；GitHub 当前提供 Issue/PR 正文及评论数，不抓取评论正文。
- 可打开已保存笔记、导出 Markdown，或用已有资料重新生成报告。已保存笔记是原始快照，重新生成不覆盖它，更新结果可导出。
- 来源引用可追溯到实际取得的链接，但不保证结论正确，重要内容请核对原文。

插件不会读取浏览器 Cookie，不接收 AI 供应商密钥。检索关键词经通用宿主网络能力发往公开来源，资料摘要与关注领域发往已配置的 AI 供应商。最近 30 次结果留在当前设备；自动保存的笔记按工作区原有机制同步。插件运行于可信客户端环境，不是强隔离 JavaScript 沙箱。

## 开发

需要 Bun 1.3.14 或更新版本。普通用户无需运行以下命令。

```sh
bun install --frozen-lockfile
bun run check
bun run test:live  # 仅验证 Bun 来源请求，不验证宿主或浏览器
bun run dev        # 127.0.0.1:4178，仅提供插件包文件
bun scripts/ui-preview.ts  # 127.0.0.1:4179，明确标注的模拟宿主 UI 验证
```

在兼容的开发宿主中使用 `http://127.0.0.1:4178/manifest.json` 安装开发包。代码变化后重新构建、安装更新包并刷新宿主；开发服务不承担研究业务。

检查包含类型、确定性测试与单文件构建。浏览器 UI 验证采用模拟来源、AI 和笔记存储，不代表真实来源或桌面时钟已完成联调。构建输出 `dist/main.js`、清单和许可证。发布资产中的清单必须与仓库根清单完全一致，且只包含一个入口 JS 文件；兼容宿主正式发布前，Release 必须标记预发布。

## 宿主边界与许可证

来源请求、解析、排序、查询规划和报告编排全部随插件打包。只使用通用网络、AI、设置、存储、笔记与调度 API；不增加来源专用宿主路由、SDK 类型或研究服务。

采用 AGPL-3.0-or-later。借鉴 Last30Days 的多来源研究思路，但不打包或调用它。参见[第三方声明](THIRD_PARTY_NOTICES.md)。
